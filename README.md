# Распознавание буровых журналов

Windows-приложение для распознавания рукописных буровых журналов постоянного шаблона, ручной проверки и экспорта в Excel.

## Что уже умеет MVP

- открывать PDF, PNG, JPG, TIFF и BMP;
- автоматически разворачивать страницу в альбомную ориентацию;
- выравнивать скан относительно эталонного бланка;
- показывать скан и редактируемые поля рядом;
- распознавать страницу локально через PaddleOCR;
- распознавать страницу через Gemini API с возвратом строго заданных полей;
- подсвечивать пустые и подозрительные значения;
- сохранять проект с ручными исправлениями;
- экспортировать все страницы в один файл Excel;
- сохранять исправления оператора в `corrections.jsonl` для дальнейшего улучшения модели.

## Установка в Windows

Рекомендуется Windows 10/11 и Python 3.11 x64.

1. Распакуйте папку программы.
2. Запустите `install.bat` (либо русскую обёртку `Установить.bat`).
3. После установки запустите `run.bat`.

Для локального распознавания дополнительно запустите `install_local_ocr.bat`. Модели PaddleOCR загружаются при первом запуске, после чего распознавание может работать без интернета.

Установщик локального OCR заранее загружает модели в видимом окне консоли. В приложении обработка одной страницы выполняется по трём этапам, которые отображаются в строке состояния. Ускоритель oneDNN/MKLDNN отключён из-за несовместимости некоторых сборок PaddlePaddle с процессорами Intel под Windows.

## Gemini OCR

Получите API-ключ в [Google AI Studio](https://aistudio.google.com/app/apikey). Откройте **Настройки**, вставьте ключ и оставьте модель `gemini-3.8-flash`. Ключ хранится через диспетчер учётных данных Windows и не записывается в файл проекта.

Скан передаётся во внешний сервис Google только после нажатия **Gemini OCR**. Локальный режим не вызывает Gemini API.

Во время запроса открывается окно с текущим этапом и таймером. Скрытые повторные запросы отключены: серверная ошибка показывается сразу. Если Gemini не ответит за 120 секунд, запрос завершится понятной ошибкой вместо бесконечного ожидания.

## Работа с программой

1. Нажмите **Открыть сканы** и выберите один PDF или несколько изображений.
2. Проверьте, что рамка формы совпадает со сканом.
3. Запустите локальное или облачное распознавание.
4. Переключайтесь между страницами кнопками **Назад** и **Вперёд**.
5. Исправьте значения в шапке, таблице и подвале.
6. Нажмите **Проверить**, затем **Экспорт в Excel**.
7. Сохраните рабочий проект в формате `.bjproj`, чтобы продолжить позже.

## Сборка обычного EXE

На компьютере Windows после установки зависимостей запустите PowerShell-скрипт:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\build_exe.ps1
```

Готовая папка появится в `dist\BoreholeJournalOCR`. Формат `onedir` выбран намеренно: он надёжнее для PySide6, OpenCV и локальных OCR-моделей, чем один огромный EXE.

Сборщик не включает PaddleOCR в процесс интерфейса. Локальное распознавание запускается отдельным скрытым процессом из `.venv`, созданной установщиком. Это изолирует нативные библиотеки Paddle: их авария не может закрыть редактор.

Для локального режима EXE должен оставаться в стандартной папке `dist\BoreholeJournalOCR` внутри распакованного проекта. Рядом с проектом должны сохраняться `.venv` и папка `app`.

## Сборка на GitHub

Workflow `.github/workflows/build-windows.yml` автоматически проверяет проект и собирает Windows-приложение на Python 3.11 x64. Он запускается при отправке изменений в ветку `main`, по тегам `v*` и вручную во вкладке **Actions**.

После успешной сборки скачайте артефакт `BoreholeJournalOCR-Windows`. Для локального OCR в распакованной папке один раз запустите `install.bat`, затем `install_local_ocr.bat`. Готовое приложение находится в `dist\BoreholeJournalOCR\BoreholeJournalOCR.exe`.

## Ограничения первой версии

- Локальный OCR хуже облачного распознаёт слитный и бледный почерк.
- Табличные строки соответствуют 19 печатным строкам бланка. Описание одного слоя может занимать несколько строк.
- Абрис сохраняется как примечание; графические элементы не переводятся в чертёж автоматически.
- Результат OCR всегда требует проверки специалистом: программа не заменяет инженерно-геологический контроль.

## Журнал ошибок

Собранное Windows-приложение записывает сообщения и аварийную диагностику в:

```text
%LOCALAPPDATA%\BoreholeJournalOCR\borehole_ocr.log
```

При запуске дочерних процессов PaddleOCR используется ранний `multiprocessing.freeze_support()`, чтобы собранный EXE не запускал рекурсивно новые копии интерфейса.

## Структура данных

Каждая строка содержит:

- номер слоя;
- глубину от/до;
- мощность или интервал мёрзлого слоя;
- описание грунта;
- номер образца;
- глубину отбора;
- сведения о воде.

Сохранённый `.bjproj` — обычный JSON-файл в UTF-8. Его можно архивировать вместе с исходным PDF.
